# Дневник питания

Статическое семейное приложение Кати и Лизы: календарь, меню, рецепты, редактирование продуктов и общие покупки. Без сборки, серверной базы, внешних шрифтов и CDN.

## Запуск и публикация

Из корня: `python3 -m http.server 8000`. Открывайте через HTTP, загрузка JSON через `file://` не поддерживается. Workflow `.github/workflows/pages.yml` публикует сайт при push в `main`; Settings → Pages → GitHub Actions. Зависимости для сайта не нужны. Рабочая копия задачи уже изолирована, дополнительные worktree для запуска не нужны.

## Источники и периоды

- До 8 ноября 2026 года доступна историческая версия из `data.json` и `ingredients.json`.
- 8–30 ноября 2026: `Menu_noyabr_8-30_Liza_Katya.docx`, 23 новых дня, покупки с учётом приобретённого 7 ноября. Капуста исключена.
- С 1 декабря 2026: `Menu_Katya_Liza_30_dney_novaya_versiya.docx`, новый повторяющийся 30-дневный план, соответствующие рецепты и покупки. В месяце из 31 дня на 31-е используется день 1; закупки учитывают дополнительный день. В феврале учитываются только существующие даты.

Новые данные, состав блюд, выбранные ориентировочные порции, таблица энергии и рецепты находятся в `menu-periods.json`. `menu-plans.js` выбирает период и рассчитывает покупки. Названия блюд перенесены из документов; для приготовления используются короткие рецепты документов и стандартные способы приготовления по составу. Калорийность после адаптации и точная смета в новых документах не рассчитаны. Бюджет на еду — лимит 24 000 ₽, а не обещанная стоимость закупки.

## Калории и замены

Для новых меню обеих участниц показаны продукты, вес/объём, средние ккал на 100 г/мл и оценка калорий порции. Выбраны порции в рамках ориентиров документа: например, курица 115 г готовой, сухая крупа 50 г, картофель 175 г. Для Кати это начальная оценка, порция по аппетиту. Неопределённая небольшая сладость считается как печенье 15 г, «фрукт» — как яблоко; альтернативы через `/` рассчитываются по первому варианту. Значения отличаются по маркам, соусам и фактическому составу. Мясо, сухие крупы и остальные продукты имеют явно подписанное состояние. Итог дня складывается из показанных значений; не подгоняется искусственно к 1 500 ккал. БЖУ для новых меню не выдумываются.

Кнопка «Изменить» открывает отдельные продукты. Можно поменять вес или ккал на 100 г/мл по этикетке: калории порции пересчитаются. Также можно ввести готовую калорийность, заменить продукт/блюдо, добавить или удалить позицию. Новые позиции сохраняются в подсказках. Пустая калорийность отличается от нуля; неполная сумма отмечается явно. Ручные изменения относятся к профилю и конкретной дате, сохраняются при смене базового документа. Доступен возврат к исходному меню.

## Покупки

План считается по базовым оценочным порциям двух участниц, а не по точной смете документа. Ручные замены в дневном меню не пересчитывают этот план автоматически. Продукты связаны со всеми блюдами, общие отметки синхронизированы, счётчики считают уникальные позиции. Чек-лист и группы сворачиваются, состояние сохраняется.

Для магазина указаны сухие крупы и макароны, сырой картофель, сырое мясо/филе, упаковки молока, десятки яиц, банки консервов. При пересчёте приготовленного мяса в сырьё использованы оценочные выходы 75% для мяса и 80% для рыбы; закупка округляется вверх до упаковки/удобного веса, поэтому помечена как ориентир. Приготовленный рис не предлагается покупать по массе порции. Уже имеющиеся рис и картофель выделены для проверки дома: неизвестные запасы приготовленного продукта не выдаются за измеренный сухой/сырой запас и не предполагаются пригодными весь месяц.

Ноябрьские приобретения по документу предзаполнены как купленные один раз. Фактический остаток и срок после вскрытия нужно сверять дома. Молоко и яйца учитываются упаковками с переносом планового остатка; можно выбрать объём молока и изменить начальный запас. Креветки отмечены как необязательная покупка при наличии бюджета. Запасы и докупки разделены, бытовые товары в пищевой список не включаются.

## Сохранение и интерфейс

Профиль, дата, продукты и правки меню, библиотека блюд, покупки, настройки упаковок и свёрнутые группы хранятся в localStorage. Между устройствами синхронизации нет; вкладки одного браузера обновляют покупки через событие storage. Покупки отдельные для каждого месяца. История отмены покупок действует до перезагрузки.

«Сегодня» определяется по Москве. Календарь показывает реальные дни недели; время приёмов пищи зависит от фактического буднего/выходного дня. Аватары — сгенерированные реалистичные котята, значки — SVG, ресурсы локальные. Иконка подготовлена по приложенному изображению. Анимации учитывают системное уменьшение движения.

## Проверки

- `python3 -m unittest discover -s tests -v` — исторические исходные данные.
- `node tests/menu-periods.test.js` — периоды, новые документы, калории и единицы покупок.
- `node tests/shopping-plan.test.js` — историческая модель остатков и упаковок.
- `python tests/browser_periods.py` — все 23 ноябрьских и 30 будущих дней для обеих участниц, суммы по продуктам, редактор, смена периода и покупки.
- `python tests/browser_calendar.py` — календарь, високосный год, месячные покупки и миграция правок.
- `python tests/browser_workflow.py` — сохранение и редактирование меню.
- `python tests/browser_shopping.py` и `python tests/browser_ingredients.py` — регрессия исторической октябрьской модели покупок, общих отметок, сворачивания и оформления.

Для браузерных проверок нужен запущенный сервер, Python Playwright и Chromium. `CHROMIUM_PATH` поддерживается тестом редактора.
